Time-clock ingestion and attendance reconciliation

Clock-event integration and cross-checking

Clock events become more than an isolated device lookup. They are transformed into daily records that can be compared with attendance reports and staff lists.

Technical implementation

I implemented Python ingestion from the time-clock API into daily BigQuery partitions. SQL transformations separate shifts and cross-check events against attendance reports; device and latency audits are available.

What it solves

It helps detect report entries without clock events, clock events without report entries and other differences requiring review. It provides a shared foundation for distinguishing device records from administrative entries.

Flow and scope

The API is queried by date and each partition is replaced to avoid duplicate loads. Data is normalized and reconciliation views are published, with specific outputs to Sheets summaries.

  • Read retries and device normalization.
  • Shift splitting and handling of repeated clock events.
  • Classification of matches and differences; review remains a human task.
