Detecting missing data and inconsistencies

Data auditing for operational review

A dashboard brings findings from different sources into the same structure: rule, severity, date and location. The team can prioritize review before interpreting metrics.

Technical implementation

I versioned SQL queries that build a rule catalog, daily coverage and a unified findings table in BigQuery. Superset consumes that output; Python tools complement inventory and review.

What it solves

It exposes omissions and contradictions that aggregate totals can hide: sites without reports, repeated people, incomplete times or clock events without administrative records.

Flow and scope

Rules compare expected calendars, recent volume and person-and-shift data. They generate findings for review; they do not automatically correct sources or guarantee that unflagged data is correct.

  • Explicit rules and shared severity levels across sources.
  • Checks for coverage, volume, identifiers and shift duration.
  • Internal view with sensitive information restricted by access.

Data flow

Source
Reports, staff lists and clock events
Processing
SQL auditing rules
Output
Findings for review

The audit reads source data and publishes evidence of differences. An authorized person makes corrections in the source system.
