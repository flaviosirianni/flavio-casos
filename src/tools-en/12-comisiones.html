Goal and commission simulation

Simulation web app and BI integration

Management adjusts thresholds and rates and compares results with the baseline policy. Scenarios allow changes to be evaluated without applying an actual payout.

Technical implementation

I built an Apps Script web app with tiered calculations and presets in Sheets. Synchronization processes read Grow datasets, retain goal and commission history and prepare a reporting table with posted and projected results.

What it solves

It allows incentive policies to be compared against production and goals without rebuilding formulas for every scenario. History avoids replacing closed months during each synchronization.

Flow and scope

Users select months and technicians, change global parameters and recalculate. The output shows details and aggregates; presets store reusable configurations.

  • Commission on production exceeding each tier’s threshold.
  • Rates by category and comparison against a baseline.
  • Goal and commission history, with closed months preserved.

Data flow

Source
BI datasets and history
Processing
Scenario engine
Output
Comparison and presets

Datasets supply goals and production; the engine recalculates scenarios. Saving a preset preserves parameters without making a payment.
